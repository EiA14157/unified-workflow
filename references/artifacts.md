# Artifacts and interface

- Decide whether the user wants a new artifact, a targeted edit, or an extraction. Keep required formatting and untouched content intact. For a new design, set a clear hierarchy around the user's primary task. For a small edit, do not redesign unrelated parts.
- Use format and host guidance only as required. Check the result in its intended viewer when available: opening/rendering for a document, viewport and keyboard behavior for interactive UI, or fresh top-to-bottom execution for a runnable notebook. For a notebook that cannot execute, report that limit rather than trusting old outputs.
- Prioritize checks that can invalidate the deliverable, such as hidden content, broken links, a clipped form, or a failed interaction. Record the observed defect at the affected page, element, or file and verify it after the change.
